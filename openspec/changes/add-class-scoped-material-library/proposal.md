## Why

项目需要让教师和学生在各自班级内安全使用教学材料，避免未登录访问、学生越权上传以及跨班读取。当前仓库仅有 OpenSpec 配置，没有应用实现或既有能力规格，本变更定义可独立启动和验收的最小应用。

## What Changes

- 教师、学生通过账号密码登录；未登录访问受保护页面跳转登录页，受保护 API 返回未认证错误。
- 每个用户只属于一个班级；服务端根据已认证用户的角色和班级执行授权，学生上传被拒绝，跨班材料访问被拒绝。
- 教师上传文件及材料记录到本项目材料库，自动归属教师所在班级；本班教师和学生可以查询列表并读取材料。
- 密码仅以安全哈希形式持久化；密钥仅通过服务端环境变量提供。
- 使用 Docker Compose 启动，持久化数据与上传文件，提供 GET /health。
- 预置样本数据：提供 A/B 两个班级、每班用于验收的教师和学生样本账号，以及名称和内容可区分所属班级的样本材料；这些数据仅用于验证登录、角色权限、班级隔离和本班材料查询。
- 明确文档与运行交付：README 包含“价值、场景、不做”三行说明及 Docker 启动方式；提供 Dockerfile、Compose 配置和 .env.example，后者仅提供环境变量名称及占位说明，不包含真实密钥。
- 本次不包含多班教师、上传时选择班级、公开注册或管理后台、向量检索、检索问答、外部知识库对接。

## Non-goals

- 不做多班教师、上传时选择班级、公开注册或管理后台。
- 不做向量检索、检索问答、对话助手或外部知识库对接；知识库仅保存上传文件及材料记录，并提供本班材料查询与读取。
- 不做作业提交与批改、SSO 或生产高可用（HA）；保持本次账号密码登录与单实例 Docker Compose 部署范围。

## Capabilities

### New Capabilities

- `user-auth`: 账号密码认证、会话、页面与 API 登录保护以及密码存储约束。
- `class-access-control`: 单班归属、教师上传权限、服务端班级隔离。
- `material-library`: 本地文件与材料记录持久化、本班列表以及受保护材料读取。
- `app-runtime`: Docker Compose 启动、环境变量密钥配置、持久化与健康检查。

### Modified Capabilities

无。当前没有既有能力规格。

## Impact

- 新增应用页面、认证和材料 API、用户/班级/会话/材料数据模型及私有文件存储。
- 新增数据库、密码哈希和会话依赖，容器构建及 Compose 配置、初始化命令和运行文档。
- 验收覆盖两个班级的教师和学生、直接调用接口的越权尝试、文件与记录一致性和容器重启后的持久性。
- 本轮仅生成此变更的规划文档，不修改业务代码。
